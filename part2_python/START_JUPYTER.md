# Open Capstone Part 2 in Jupyter

1. Extract the complete Capstone_Part2_Jupyter.zip. Keep the files and folders together.
2. Open the Capstone_Part2 folder in File Explorer. In its address bar type powershell and press Enter.
3. Run these commands, one line at a time:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
.venv\Scripts\python.exe -m jupyterlab Capstone_Part2.ipynb
```

4. JupyterLab should open in your browser. Select the Python 3 kernel for this environment.
5. Select **Run > Run All Cells**. If asked whether to trust the notebook, trust it only after reviewing its code.

The notebook has already been executed and includes tables, charts, CLI answers and test results.
The standalone notebook download is useful for reading, but rerunning requires the companion
Python modules and data from this ZIP. No external account or dataset download is needed.

If Jupyter is already installed in your selected environment, open the notebook there after
installing requirements.txt. Python 3.11 or later is recommended. Using the explicit virtual
environment python path above avoids PowerShell activation-policy issues.

## Where to find results

- Capstone_Part2.ipynb: step-by-step executed notebook.
- notebook_outputs/processed/: data and parameters generated by notebook cells.
- notebook_outputs/figures/: four charts shown inline in the notebook.
- notebook_outputs/pipeline.log: notebook audit trail, including deliberate DEBUG/ERROR demonstrations.
- notebook_outputs/app.log and cli_examples.json: real CLI runs, including expected invalid input.
- notebook_outputs/integration/: standalone script integration results.
- notebook_outputs/test_results.txt: ten project tests.
- reports/: the original detailed guide and two-page methodology report.

The original scripts remain included because the assignment specifically requires a Python
pipeline and CLI. The notebook calls those functions and runs app.py in subprocesses. The
additional notebook uses the same hourly priority and does not replace the project logic.

The full project has local Git history. It has not been published to GitHub. Source details,
weather priority, label definitions, limitations and publication instructions are in README.md.

## Execution verification

Every code cell was run in order using an in-process IPython session, with actual rich
outputs saved in the notebook. This environment blocks the local TCP/IPC connections
needed for a separate Jupyter kernel, so launching the browser-based Jupyter interface
here was not verified. The supplied .ipynb uses the standard Python 3 kernelspec for
opening in Jupyter on your computer. Deliberate ERROR examples are caught validation
demonstrations and are not unhandled cell failures.
